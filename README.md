# Comet-Calc-Frontend — кометы, SPA (ЛР6)

Тема: расстояние кометы от Солнца по её координатам на небесной сфере. Услуга — **комета**.

ЛР6: завершение интерфейса пользователя на React + TypeScript. Данные берутся из веб-сервиса Comet-Calc-Backend
(ЛР4) через прокси Vite; если сервис недоступен, гость видит mock-данные. Состояние — Redux Toolkit:
фильтр плитки, кометы (запросы через thunk и клиент, сгенерированный из Swagger), пользователь.
Вход и выход — через axios, результат передаётся в Redux вручную. Компоненты — React-Bootstrap, маршруты — React Router.

Стек: React 19, TypeScript 6, Vite 8, Redux Toolkit 2 + React Redux 9, axios, swagger-typescript-api,
React Router 7, React-Bootstrap 2 (Bootstrap 5).

## Запуск

```
npm install
npm run dev            # http://localhost:3000
npm run build          # сборка в dist/
npm run lint           # oxlint
npm run generate-api   # кодогенерация src/api/Api.ts из ../Backend/docs/swagger.json
```

Бэкенд запускается по README Comet-Calc-Backend (`docker compose up -d`, `go run ./cmd/comets`).
Без бэкенда фронтенд тоже работает: лента и плитка показывают mock-данные с плашкой «Веб-сервис недоступен».

Кодогенерацию можно выполнить и по адресу работающего сервиса:
`npm run generate-api -- http://localhost:8080/swagger/doc.json`.

## Прокси (CORS)

Браузер обращается только к адресу фронтенда, Vite перенаправляет запросы (`vite.config.ts`):

| Адрес во фронтенде | Куда | Зачем |
|---|---|---|
| `/api/…` | `http://localhost:8080/api/…` | методы веб-сервиса |
| `/s3/…` | `http://localhost:9000/…` (Minio) | фото и видео: `/s3/comets/halley.jpg` |

Веб-сервис отдаёт полные адреса Minio (`http://localhost:9000/comets/…`), фронтенд переводит их на `/s3/…`
(`toS3Url` в `src/modules/cometsApi.ts`). Адреса можно переопределить переменными окружения:
`API_TARGET=http://localhost:8081 npm run dev`, `S3_TARGET=…`.

## Гость и пользователь

| | Гость | Пользователь (после входа) |
|---|---|---|
| Главная, лента, плитка, фильтр | да | да |
| Лайк в ленте | нет (сердце неактивно) | да |
| «Добавление» в меню | недоступно (серое) | страница добавления |
| «Удалить» на карточке | нет | у своих комет (`is_mine = 1`) |
| Последний пункт меню | **Вход** | **Выход** |

Если веб-сервис недоступен, показываются mock-данные, а лайки, удаление и добавление недоступны.

Диаграмма прецедентов — `docs/use-case.png`.

## Страницы

### Меню (внизу на всех страницах)

| Пункт | Что делает |
|---|---|
| Лента | переход на `/feed` — первая опубликованная комета |
| Добавление | гость — недоступен; пользователь — `/add` |
| Плитка | переход на `/comets` |
| Вход / Выход | гость — `/login`; пользователь — выход (`POST /api/users/logout`), переход на ленту |

Во время выхода вместо значка крутится индикатор загрузки, пункт заблокирован.

### Главная — `/`

- значок, заголовок «Кометы», описание; у пользователя — «Вы вошли как …»;
- сводка по всему каталогу (без фильтра плитки): число комет, самый короткий и самый длинный период;
- кнопки **Смотреть ленту** и **Открыть плитку**.

### Лента — `/feed`, `/feed/:id`, `/feed/:id?next=true`

- запрос `GET /api/comets/feed/{id}?next=true` (без id — `GET /api/comets/feed`);
- видео кометы на фоне, миниатюра фото, название, описание с кнопкой **Ещё** / **Свернуть**;
- период обращения, эксцентриситет;
- **сердце с числом лайков**: у пользователя — кнопка (`POST /api/comets/{id}/like`, `like: 1` / `0`),
  контур — лайка нет, заливка — лайк поставлен; во время запроса вместо сердца индикатор загрузки;
- кнопка **↓ (следующая)** — следующая опубликованная комета.

Удалённая, неопубликованная, несуществующая комета или нечисловой id (ответ 404 / 400) — переход на `/feed`.

### Плитка — `/comets`

- запрос `GET /api/comets?min_orbital_period=&max_orbital_period=` — значения берутся из Redux;
- фильтр по периоду обращения: слайдеры **от** и **до** (0–140 лет), **Показать** записывает фильтр в store,
  **Сбросить** возвращает исходный диапазон. Применённый фильтр и положения слайдеров сохраняются при переходах между страницами и сбрасываются при выходе;
- пока идёт запрос — индикатор загрузки, кнопки фильтра заблокированы;
- карточки: фото, название, период, лайки; клик — комета в ленте;
- у своих комет пользователя — кнопка **Удалить** (`DELETE /api/comets/{id}`, логическое удаление),
  во время запроса карточка и кнопка заблокированы.

### Вход — `/login`

- поля **Логин** и **Пароль**, кнопка **Войти** (неактивна, пока поля пустые);
- `POST /api/users/login` через axios → `access_token` сохраняется в localStorage (`comets.token`, `comets.login`),
  в Redux вызывается `setUser`; переход на ленту;
- ошибка («Неверный логин или пароль», «Веб-сервис недоступен…») — под полями;
- после обновления страницы (F5) пользователь восстанавливается из localStorage.

Тестовые пользователи — из `db/seed.sql` бэкенда (пароль у всех `comets2026`).

### Добавление — `/add` (только пользователь, гость перенаправляется на вход)

| Поле | Ограничение |
|---|---|
| Название | обязательно, до 100 символов |
| Описание | обязательно, до 500 символов |
| Период, лет | число больше 0 (запятая или точка) |
| Эксцентриситет | от 0 до 1 |
| Фото | jpeg, png, webp, gif до 10 МБ |
| Видео | mp4, webm до 50 МБ |

При входе на страницу `GET /api/comets/draft` открывает сохранённый черновик. Если его нет, форма запрашивает
только название. **Создать черновик** отправляет `POST /api/comets` и открывает второй шаг со стандартными фото и видео.
На втором шаге можно выбрать свои файлы и сразу увидеть их превью. **Опубликовать** отправляет
`PUT /api/comets/{id}/publish` с описанием, периодом, эксцентриситетом и выбранными файлами. Файлы необязательны.
Введённые поля и выбранные файлы сохраняются при переходах по страницам внутри приложения до публикации или выхода.
Во время сохранения поля и кнопка заблокированы. После публикации открывается комета в ленте.

## Redux

| Срез | Состояние | Как меняется |
|---|---|---|
| `filter` | `from`, `to` — применённый фильтр, `sliderFrom`, `sliderTo` — текущие положения слайдеров | `setSliderFrom`, `setSliderTo`, `applyFilter`, `resetFilter`; сбрасывается по `clearUser` |
| `comets` | `list`, `feed`, `isMock`, флаги загрузки, `pendingIds` (лайк / удаление), `savingDraft` | thunk через сгенерированный клиент |
| `user` | `login`, `isAuthenticated` | `setUser` / `clearUser` — вручную после запросов axios |

Thunk `fetchComets` читает фильтр через `getState()` и передаёт его в `api.comets.cometsList(...)`.
Если сервис не ответил (нет соединения или 5xx от прокси), thunk возвращает mock-данные и `isMock = true`.
Ответ на 401 (токен истёк или отозван) — пользователь выходит на клиенте.
Ответы устаревших запросов (фильтр сменили, пока шёл прошлый) отбрасываются по `requestId`.

## Фото и видео по умолчанию

Хук `useMediaSrc` (`src/modules/media.ts`) подставляет `public/DefaultComet.jpg` / `public/DefaultComet.mp4`,
если поле в комете пустое или файл не загрузился (`onError` у `<img>` и `<video>`).

## Хуки

| Хук | Где | Зачем |
|---|---|---|
| `useState` | CometsPage, FeedPage, LoginPage, AddPage, TabBar, `useMediaSrc` | слайдеры, поля форм, раскрытие описания, загрузка выхода |
| `useEffect` | CometsPage, FeedPage, HomePage | dispatch thunk при открытии и смене фильтра, id, входа; отмена запроса (`abort`) |
| `useAppDispatch`, `useAppSelector` | страницы, TabBar | доступ к Redux |
| `useParams` | FeedPage | id кометы из адреса |
| `useSearchParams` | FeedPage | признак `next` |
| `useNavigate` | страницы, TabBar | переходы и редиректы |
| `useLocation` | TabBar | подсветка активного пункта меню |
| `useMediaSrc` (свой) | CometPhoto, CometVideo | адрес файла или файла по умолчанию |
